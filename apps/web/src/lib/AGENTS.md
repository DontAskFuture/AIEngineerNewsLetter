# AGENTS.md

## Scope
This file applies to `apps/web/src/lib`.

## Architecture
- `auth.ts` owns constant-time password hashing/verification (scrypt with max-length bounds and dummy-hash fallback), React `cache()`-deduplicated session lookups (`getCurrentUser`) with 5-minute `last_seen_at` write throttling, session cookies (`ai_intel_session`, marking cookies `Secure` when `APP_BASE_URL` is `https://` or `x-forwarded-proto` is `https`), single-query per-IP/per-email/combined login-attempt throttling, hardened relative redirect validation (`getSafeRedirectPath`), allowlist/admin checks, and the `requireCurrentUser`/`requireAdmin`/`getAuthenticatedAdmin` guards used by pages, API routes, and server actions.
- `env.ts` loads and memoizes process env into a typed `loadWebEnv()` snapshot: OpenRouter key/model (default `~deepseek/deepseek-flash-latest`, matching the shared scoring config's paid model), app base URL/timezone, `FEED_SHOW_WHY_RELEVANT`, allowed/admin emails, session length, and personal brand settings (`BRAND_AUTHOR_NAME` defaulting to `"Michael"`, `BRAND_AUTHOR_BIO` defaulting to generic AI engineering curation text, `BRAND_X_URL`, `BRAND_LINKEDIN_URL`, `BRAND_GITHUB_URL`).
- `crawler.ts` enqueues `fetch-source-endpoint` (via a single multi-row `INSERT`) and `score-documents` jobs (`triggerCrawl`, `triggerScoring`, `enqueueProfileScoring`) directly into `pgboss.job` and reads recent crawl job status/summary in parallel for the admin dashboard.
- `dashboard.ts` builds the source registry, endpoint health, category breakdown, and recent fetch attempts shown on `/admin`. The public source list is the layout footer, not this snapshot.
- `operations.ts` aggregates pg-boss queue summaries (`fetch-source-endpoint`, `score-documents`, `send-daily-newsletter`, `send-daily-admin-report`), recent crawl/scoring/queue error logs, newsletter delivery summaries (`newsletterSummary`, `recentNewsletterSends`), and system hygiene counts (`systemHygiene`) for admin incident diagnosis and exposes `checkDatabaseHealth()` for `/api/health`; it is read-only and never executes worker logic.
- `scoring.ts` scores a profile's unscored documents by asking Decider Flash for relevance and story topic, then DeepSeek for Michael's Take on the daily top 10 only (selecting bounded `left(body_text, 2000)` previews, deduplicating syndicated candidates across the run via `deduplicateScoringCandidates`, re-verifying the profile interest statement before persisting `document_scores` and `documents.story_topic`, and marking the job failed if all batches fail). It tracks progress through `scoring-tracker.ts` and exposes `getScoringStats`/`getScoringStatsBySource` for admin. Its `scoreUnscoredDocuments` is the inline (web-process) scoring path used by `app/api/score-all`, separate from the worker's own scoring job. The web path scores up to `scoringConfig.maxDocumentsPerRun` per request.
- `scoring-tracker.ts` reads and writes `scoring_jobs` rows: starts a job, updates batch progress, marks stale (>30 min) running jobs as failed, and returns current/history state (prioritizing active `"running"` jobs) for `/api/scoring-status`.
- `openrouter.ts` wraps OpenRouter chat completions for DeepSeek prose: `writeStoryOpinions` (Michael's Take) and `summarizeTopStoriesForProfile` (industry-trend briefing). Relevance scoring is not a chat call; `scoring.ts` uses `decideStoryRelevanceBatch` from `@ai-intel/shared`. Chat calls use candidate-scaled `max_tokens` (`4096` for summaries and up to `8192` for opinion batches), `reasoning: { effort: "low" }`, `response_format: { type: "json_object" }`, in-loop JSON contract validation, and retry/backoff. Retry-vs-fall-through is decided by `decideRetry`/`extractBodyError` from `@ai-intel/shared`, and chat requests are bounded by a 60s `AbortSignal.timeout`.
- `personalized-feed.ts` is the feed's core module: profile CRUD (with length bounds, active-profile cap `MAX_ACTIVE_PROFILES_PER_USER = 10`, duplicate-name and last-profile-delete guards, automatic score/cache invalidation plus `enqueueProfileScoring` when an interest statement changes), story curation CRUD (`saveStoryCurationNote`, `setStoryPinned`, `setStoryHidden` backed by `story_curations` with automatic public-feed cache invalidation), single-wave parallel profile/candidate/score/read-state/curation loading, 30s public-feed snapshot caching (`getPublicAiEngineerFeedSnapshot`), pre-computed-score ranking via `computeAdjustedStoryScore` and `parseWhyRelevantMetadata` (prioritizing pinned stories first, excluding hidden stories from top 10 and public view, `score >= 40` required for non-pinned top stories, syndicated title deduplication via `normalizeStoryTitle`, and a per-topic cap of `MAX_TOP_STORIES_PER_TOPIC` with a backfill pass so one topic cannot fill the shortlist), unread top-10 promotion that keeps pinned stories at the top and prioritizes qualifying scored stories ahead of unscored stories, and the cached (`ranking_cache`, keyed by `top-stories-summary:v5`, window, interest statement, and pre-read story/note fingerprint) profile-level top-stories Trend & Insights briefing.
- `newsletter-subscribers.ts` manages public email newsletter subscriptions (`subscribeToNewsletter`, `unsubscribeFromNewsletterByToken`, `getActiveNewsletterSubscriberCount`) backed by `newsletter_subscribers` and `normalizeSubscriberEmail` from `@ai-intel/shared`, and records anonymized RSS feed client polls (`recordRssFeedClientPoll`) in `rss_feed_clients`.
- `read-tracking.ts` records `document_reads` (`markDocumentRead`) and joins read state onto arbitrary document lists (`applyReadStateToDocuments`).
- `document-read-list.ts` manages the separate `user_document_read_list` save list (add/remove/list) and builds the `/read-list` page snapshot in a single query (`leftJoin` with `document_reads` and `left(body_text, 2000)`).
- `formatters.ts` holds presentation-only helpers (relative/absolute time, compact numbers, percent, duration, category label, text truncation) with no DB or network access.

## Implementation Guidance
- Keep DB access and external API calls inside these modules; route and page files should call into `lib`, not query Postgres or OpenRouter directly.
- `env.ts` caches its result in a module-level variable; treat env values as effectively static for the life of the process rather than re-reading `process.env` elsewhere.
- Relevance and story topic come from Decider Flash via `decideStoryRelevanceBatch` for every story in the run. Michael's Take uses `selectOpinionModelCandidates` for the daily top 10 only, and the industry-trend briefing uses `selectSummaryModelCandidates`; `env.openRouterModel` is the final fallback for those two prose calls only.
- Do not reimplement OpenRouter status handling here; call `decideRetry`/`isFreeTierModel`/`extractBodyError` from `@ai-intel/shared` so the web and worker clients stay in sync. A failed candidate must `break` to the next model, never `throw`, or the remaining pool and the paid backstop are skipped.
- `crawler.ts` enqueues jobs with a `singleton_key` and `ON CONFLICT DO NOTHING`; new job-enqueue helpers should follow the same idempotent pattern instead of inserting duplicate rows.
- `personalized-feed.ts` and `document-read-list.ts` both take an explicit `userId`/`readStateUserId` scoping parameter; never build a query that reads or writes another user's rows without it.
- Prefer extending `scoring-tracker.ts` over adding new ad hoc progress-state tables when tracking future long-running jobs.
