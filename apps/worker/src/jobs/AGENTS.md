# AGENTS.md

## Scope
This file applies to `apps/worker/src/jobs`.

## Architecture
- `fetch-source-endpoint.ts` executes fetches and converts remote content into raw and normalized records.
- `score-documents.ts` scores unscored documents for a given user profile, paging until the lookback window is done or `SCORING_MAX_DOCUMENTS_PER_RUN` is hit. Decider Flash assigns relevance and story topic for every story. DeepSeek writes Michael's Take only for the daily top 10. It writes `document_scores` and `documents.story_topic`, with progress tracked in `scoring_jobs`.
- `send-daily-newsletter.ts` sends each active user a daily brief for their default active profile, falling back to their earliest-created active profile, through `services/smtp.ts`, and records successful sends in `newsletter_sends`. Its pure selection and HTML/text rendering helpers (`selectTopStories`, `buildNewsletterHtml`, `buildNewsletterText`) are covered by `send-daily-newsletter.test.ts`.
- `send-daily-admin-report.ts` aggregates daily subscriber counts (email + RSS), server/DB/queue health, and 24-hour source crawl statistics (`collectAdminReportSnapshot`) and sends a daily operations summary to `ADMIN_EMAILS` via `services/smtp.ts`. Its email-parsing and HTML/text rendering helpers (`parseAdminEmails`, `buildAdminReportHtml`, `buildAdminReportText`) are covered by `send-daily-admin-report.test.ts`.
- `cleanup-crawled-documents.ts` prunes expired normalized documents, raw payload rows/files (verifying `storageKey` stays within `RAW_STORAGE_DIR`), expired `auth_sessions`, expired `ranking_cache` entries, and `auth_login_attempts` older than 7 days using the worker TTL settings.
- `html-links.ts` owns listing-page link extraction: the `parserKey` selector registry (`htmlParserConfigs`) and `extractArticleLinks`. It is a pure, dependency-light module so listing strategies can be verified against live HTML without a database. Covered by `html-links.test.ts`.

## Implementation Guidance
- Treat every job as rerunnable.
- Use content hashes and canonical URLs consistently for fetch jobs.
- Fetch jobs should skip normalized document inserts and article-page fetches when the canonical URL already exists in `documents`.
- Fetch jobs should validate source URLs (http/https only, standard ports 80/443, no embedded credentials), redirects (including redirect loop detection and cancelling 3xx response bodies), and DNS resolution before egress, blocking non-http(s), off-domain, private, link-local, loopback, multicast, NAT64, and metadata-style targets as non-retryable `FetchBlockedUrlError`s. Relative RSS item links should be resolved against `baseUrl`, and malformed individual feed links should be skipped without failing the entire feed.
- Crawl inserts are capped per fetch/source pass rather than by lifetime database totals; dedupe still relies on canonical URLs.
- Remote fetches should enforce timeout and response-size bounds before persisting raw payloads or parsing HTML/RSS.
- RSS ingestion should store plain-text summaries and body text by stripping HTML and rejecting CSS-heavy feed noise; when feed text is unusable, fetch the linked article with Readability (bounded per feed pass).
- Fetch jobs retry transient network failures, HTTP 429, and HTTP 5xx responses before recording a failed attempt, and failed attempts should preserve the HTTP status when available.
- HTML listing pages should use bounded-concurrency article fetches through the shared fetch helper rather than ad hoc sequential `fetch()` calls.
- HTML article extraction should preserve publication dates from common article/meta tags when available instead of relying only on discovery time.
- Source-specific HTML extraction should use endpoint `parserKey` selectors where known and fall back to the generic same-path strategy only for simple listing pages.
- Add a `parserKey` only when the generic same-path strategy fails, which happens when a listing page links to sibling sections (Epoch AI, Physical Intelligence's `/blog` and `/research`, DeepSeek's `/updates` linking to `/news/<slug>`) or is served from the site root so the listing path is empty (LMArena).
- A listing page that links only to off-domain URLs cannot produce documents, because `extractArticleLinks` enforces same-origin. Prefer a feed, or drop the source, rather than adding a parser for it.
- HTML listing sources return HTTP 200 even when they yield zero links, so status codes alone do not prove a source works. Verify new or re-pointed HTML endpoints by running `extractArticleLinks` against the live page and confirming a non-zero link count.
- Scoring jobs create a `scoring_jobs` row at start, select bounded `left(body_text, 2000)` previews, deduplicate syndicated candidates across the entire run with `deduplicateScoringCandidates`, scale `max_tokens` with candidate count (up to `8192` with `reasoning: { effort: "low" }` so reasoning models do not truncate JSON), re-verify the profile's interest statement before persisting each batch, update `scoring_jobs` per batch with scored/failed counts, and mark the job `"failed"` when all batches fail (`scoredTotal === 0 && failedTotal > 0`).
- Scoring jobs read batch size, the per-run ceiling, the Decider Flash model, and the DeepSeek opinion candidates from `packages/shared/src/scoring-config.ts`. Relevance calls `decideStoryRelevanceBatch` (Decisions API, 15s timeout, bounded concurrency). Opinion calls use DeepSeek chat completions only for the daily top 10.
- Scoring jobs may receive `documentIds` to restrict work to newly inserted documents; broad scoring stays bounded by the worker max-document ceiling and lookback env controls.
- Decider Flash returns a topic choice plus a score on four ordered relevance levels, mapped back to the 1-100 scale. Every scored story stores `Take withheld.` or the off-topic note, with `opinion_model` `not_required`, until it is in the daily top 10. A failed decision is counted failed, remembered for the rest of the run, and left unscored. A failed opinion call keeps the score and is retried on a later run. Each run also classifies recent documents that still have a null `story_topic`, paging until that window is done or the run ceiling is hit. `selectDiverseShortlist` picks the same top 10 the newsletter sends (last 24 hours, score at least 40, topic and source caps, pins included). Pending takes outside that shortlist are rewritten to `Take withheld.` so they do not call DeepSeek.
- The DeepSeek opinion prompt receives the profile's display name, interest statement, and `extractDocumentPreview` excerpts, and asks for JSON (`matchedSignals`, `whyRelevant`) enforced with `response_format: { type: "json_object" }` and validated via `parseStoryOpinionsResponse`. It must not assign a score.
- Retry OpenRouter on 429 and 5xx with exponential backoff (up to 3 retries), except that any failure from a free-tier (`:free`) candidate falls through to the next model immediately, with no backoff. That policy lives in `decideRetry`/`isFreeTierModel`/`extractBodyError` in `@ai-intel/shared`; call it rather than re-deriving status checks here.
- DeepSeek opinion requests must set a 60s `AbortSignal.timeout`. Decision requests use the shorter timeout in `scoringConfig.jevTimeoutMs`. A failed opinion candidate must `break` to the next model, never `throw`, or the DeepSeek fallback is skipped.
- Newsletter story selection uses `selectDiverseShortlist`: at most `MAX_TOP_STORIES_PER_TOPIC` unpinned stories per topic, then a backfill if the shortlist is still short. Pins bypass the cap but still count toward it.
- Newsletter jobs must validate `newsletterDate` (`YYYY-MM-DD`) and check `newsletter_sends` before sending so worker restarts do not duplicate a user's daily email.
- Newsletter jobs should ensure active users have a default first profile before selecting recipients, then prefer the active profile marked `is_default`, and also deliver the public curator's daily brief to active `newsletter_subscribers` (with per-subscriber `last_sent_date` deduplication, one-click `/feed/unsubscribe?token=...` links, and RFC 8058 `List-Unsubscribe` / `List-Unsubscribe-Post` headers passed through `sendTransactionalEmail`).
- Newsletter story selection joins `story_curations` (promoting pinned picks to the top, excluding hidden stories, and rendering practitioner takes labeled `{brandAuthorName}'s Take` / `Michael's Take` via `formatPractitionerTake(curatorNote, whyRelevant)`), includes cached `Today's Industry Trend · Macro Signal & Insights` bullets from `ranking_cache` alongside personal branding (`BRAND_AUTHOR_*` with generic AI engineering curation bio default) and Web/RSS links, ranks scored documents (`score >= 40`) from the last 24 hours using `computeAdjustedStoryScore` (freshness, source trust tier, and confidence), strips stored `Confidence`/`Signals` metadata via `parseWhyRelevantMetadata`, deduplicates syndicated titles with `normalizeStoryTitle`, caps stories per source domain (`MAX_PER_SOURCE`) and total count, validates `http(s):` story URLs, and falls back to source-diversified recent unscored documents when no scored stories qualify.
- Cleanup jobs should delete in batches, rely on existing foreign-key cascades for dependent feed data, and tolerate missing raw payload files.
- Log operational details, but keep return values compact and machine-friendly.
