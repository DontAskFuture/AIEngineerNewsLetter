# AGENTS.md

## Scope
This file applies to `packages/shared/src`.

## Architecture
- `types.ts` defines shared source, fetch payload, scoring payload, newsletter payload, and admin report payload types (`FetchSourceEndpointPayload`, `ScoreDocumentsPayload`, `SendDailyNewsletterPayload`, `SendDailyAdminReportPayload`); scoring payloads may include `documentIds` for targeted worker scoring.
- `types.ts` also declares the `sourceCategories` and `endpointKinds` const arrays backing `SourceCategory`/`EndpointKind`; these are a superset of what is currently seeded (see below), so a new value can be declared ahead of any source that uses it.
- `default-sources.ts` exports a single `defaultSources: SeedSource[]` array, the curated registry seed set: 136 sources with 136 endpoints total (116 `rss`, 20 `html`), across `research_feed` (6), `lab_blog` (19), `engineering_blog` (35), `community_feed` (44), and `github` (32). It spans lab blogs (including Chinese and non-US labs such as DeepSeek and Qwen, plus Apple Machine Learning, Thinking Machines Lab, and Physical Intelligence), engineering blogs, arXiv research feeds (`cs.AI`, `cs.LG`, `cs.CL`), GitHub release/commit feeds for core AI and Chinese open-source frameworks (`veRL`, `Mooncake`, `LMDeploy`, `LLaMA-Factory`, `ms-swift`, `OpenCompass`, `Dify`, `RAGFlow`, `Milvus`, `MNN`), safety and evaluation orgs (METR, Epoch AI, Alignment Forum), newsrooms and Chinese AI publications (QbitAI 量子位, ChinAI Newsletter, Pandaily, The Verge, TechCrunch, MIT Technology Review, Ars Technica, Wired, The Guardian, The Decoder, The Register, IEEE Spectrum, Quanta, InfoQ), individual feeds from prominent AI practitioners and researchers (e.g., Andrej Karpathy, Lilian Weng, Eugene Yan, Chip Huyen, Sebastian Raschka, Eric Jang, Nathan Lambert, Hamel Husain, Ethan Mollick), and industry-analysis newsletters (The Pragmatic Engineer, Ben's Bites, TLDR AI, The Neuron). The AI Snake Oil publication now publishes as AI as Normal Technology at `normaltech.ai`; the seed keeps the `ai-snake-oil` slug so existing documents stay on that source.
- Of the nine `sourceCategories` declared in `types.ts`, only five are used by any seeded source today: `lab_blog`, `engineering_blog`, `research_feed`, `community_feed`, and `github`. `social_trends`, `startup_launch`, `docs`, and `pricing` are declared but currently unused by `default-sources.ts`.
- Of the five `endpointKinds` declared in `types.ts`, only `rss` and `html` are used today; `sitemap`, `docs`, and `pricing` are declared but currently unused.
- `prompts.ts` owns shared LLM prompt templates, XML-delimited candidate rendering (`<user_profile>`, `<documents>`, `<top_stories>`), bounded profile/excerpt truncation (`MAX_PROFILE_NAME_LENGTH`, `MAX_INTEREST_STATEMENT_LENGTH`), compact `YYYY-MM-DD` date formatting, duplicate title-prefix stripping in excerpts, document preview extraction (`extractDocumentPreview`), stored `whyRelevant` metadata formatting/parsing/stripping (`formatWhyRelevant`, `parseWhyRelevantMetadata`, `stripWhyRelevantMetadata`, including the `Opinion pending.` sentinel), story title normalization (`normalizeStoryTitle`), cross-batch candidate deduplication (`deduplicateScoringCandidates`), shared confidence/freshness/tier score adjustment (`computeAdjustedStoryScore`), and response contract parsers (`parseStoryOpinionsResponse`, `parseSummarizeTopStoriesResponse`) used by both web and worker code. Covered by `prompts.test.ts`.
- `jev.ts` owns the Decisions API client for relevance and story topic. The model id is Perplexity Decider Flash (`scoringConfig.jevModel`). It holds the topic taxonomy (`STORY_TOPICS`), the 1-100 score mapping (`mapJevRelevanceScore`), the daily shortlist (`selectDiverseShortlist`, `MAX_TOP_STORIES_PER_TOPIC`, `storyTopicAtCap`), request building, response parsing, `decideStoryRelevanceBatch`, and topic-only `classifyStoryTopicsBatch` for documents that already have a score. Covered by `jev.test.ts`.
- `scoring-config.ts` owns shared scoring knobs such as batch size, the web run ceiling, the Decider Flash model id, the daily take count, and ordered OpenRouter candidate lists for opinions and summaries. Relevance no longer uses `freeScoringModelPool`; that list remains only so `ScoringModelPool` can still build its old chat-candidate order. Opinions and industry-trend summaries run DeepSeek Flash Latest (`~deepseek/deepseek-flash-latest`) alone. DeepSeek writes a take only for the daily top 10.
- `openrouter-retry.ts` owns the OpenRouter failure policy as pure functions (`isFreeTierModel`, `decideRetry`, `extractBodyError`). Free-tier candidates are never retried — the next free model is always cheaper than a backoff — while the paid backstop keeps attempt-bounded retries. `extractBodyError` normalizes OpenRouter's HTTP-200-with-`error` payloads and empty-choices responses into a status the policy can classify. Covered by `openrouter-retry.test.ts`.
- Adding a model to `freeScoringModelPool` requires probing it first: it must return the scoring prompt's JSON contract and rank an off-topic document far below on-topic ones. Several advertised `:free` models return 403 (not enabled per-account), sit permanently at 429, or hang without responding.
- `model-health.ts` owns the per-process circuit breaker (`ModelHealthTracker`, `classifyFailure`, `COOLDOWN_MS`). Cooldowns scale with how durable the failure is, and `selectAvailable` never drops a paid candidate or returns an empty list, so health state can never strand a caller with nothing to try.
- `model-discovery.ts` owns `selectDiscoverableFreeModels`, a pure filter/rank over the models API payload: `:free` only, `response_format` support required for the JSON contract, a minimum context window, a minimum completion token cap (`DISCOVERY_MIN_COMPLETION_TOKENS`), and a hard result cap so worst-case fall-through latency stays bounded.
- `model-pool.ts` composes the two into `ScoringModelPool`, the single entry point both apps use for scoring candidates (`candidates(now, fallbackModel)`). Construct it once per process — the breaker is worthless if a fresh instance is created per call.
- Seeded source endpoints should default to hourly cadence unless there is a deliberate reason to poll faster.
- `url.ts` handles canonicalization, enforces `http:`/`https:` URL protocols, and rejects URLs containing embedded credentials (`username`/`password`). Covered by `url.test.ts`.
- `curation.ts` owns pure subscriber email normalization/validation (`normalizeSubscriberEmail`, `InvalidSubscriberEmailError`), practitioner take formatting (`formatPractitionerTake`), and RSS 2.0 XML feed serialization (`buildCuratedRssXml`, `escapeXml`, `sanitizeHttpUrl`). Covered by `curation.test.ts`.
- `index.ts` is the package export surface.

## Implementation Guidance
- Keep source definitions explicit and readable.
- When expanding the registry, prefer feeds that return valid RSS/Atom and use HTML endpoints only for high-value sources without working feeds.
- HTML endpoints may set `parserKey` when the worker has a source-specific selector strategy (9 of the 20 `html` endpoints do today); endpoints without a `parserKey` fall back to the worker's generic link-extraction path, so keep keys stable because existing seeded endpoints are updated by source URL.
- `canonicalDomain` gates worker egress via `isAllowedHost` in `apps/worker`, so it must match the host actually fetched, not the site the stories point at. A feed proxied by another host (for example Hacker News via `hnrss.org`) must use the proxy's domain or every fetch is blocked.
- Endpoints sharing one upstream domain should use staggered `cadenceMinutes` so concurrent fetch workers do not rate-limit each other; the Reddit feeds are staggered at 60/75/90/105 for this reason.
- Prefer converting an HTML endpoint to `rss` whenever the site turns out to publish a feed, since feed parsing is cheaper and avoids listing-page drift.
- Weekend-quiet feeds are normal: arXiv feeds declare `<skipDays>` for Saturday and Sunday and legitimately return zero items then, so an empty arXiv result is not a broken source.
- Shared types should reflect stable contracts used by both apps.
- URL normalization rules should be conservative because they affect dedupe and document identity.
- Prompt templates should stay centralized here and keep complex formatting, HTML preview extraction, and JSON response contract validation in TypeScript helpers rather than hidden in template strings or duplicated in callers.
- Opinion prompts wrap untrusted profile and candidate fields in sanitized XML tags (`<user_profile>`, `<documents>`) and instruct DeepSeek to write critical, spicy personal Staff AI Engineer takes. They do not assign a relevance score. Decider Flash owns the score and the story topic for every story. DeepSeek writes Michael's Take only for the daily top 10 from `selectDiverseShortlist`. Other scored stories store `Take withheld.` (or the off-topic note below 40) and never call DeepSeek.
- Profile-level top-story summary prompts parameterize the shortlist size (`storyCount`), structure `takeaways` as 3-4 concise, critical bullet points for "Today's Industry Trend · Macro Signal & Insights", strip stored `Confidence`/`Signals` metadata from `whyRelevant` notes, handle `"Unscored fallback"` items without forcing relevance, preserve XML prompt-injection boundaries, and validate non-empty `summary` JSON output.
- Shared scoring configuration should live here instead of being hardcoded in web or worker business logic; model fallback order should be represented as explicit ordered candidate lists.
